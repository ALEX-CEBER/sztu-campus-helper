一、课题筛选：五个候选对比

课题实现难度主要风险二次元容纳度结论
校园办事问答（含助手） 低 数据自己写、纯前端可跑、检索算法 100 行以内 需核实学校真实流程（有解：数据标注"待核实"迭代补充） 看板娘助手天然适配（立绘+拟人文案+表情气泡） ★ 首选
课程答疑知识库（含助手） 中低 与首选同构，但需真实课程资料且答案正确性要人工把关 答疑答错"显眼"；高数等科目答案构建成本高 同上 备选
AI 校园全能助手（AIGC） 高 "全能"=范围失控，单人/双人做不完 功能多而浅，期末演示每项都拿不出手 高 不推荐
小说影视化流水线（AIGC） 高 文生图/文生视频调用多、排队久 校内模型并发有限+仅当晚开放，生成不可控；视频分镜一致性难 高 不推荐
AI 校园电台（AIGC） 中 TTS+内容生成+音频播放器 同受模型时段限制；音频资产管理繁琐；演示依赖播放效果 高（虚拟主播） 不建议
筛选原则回顾：① 课程硬约束优先（模型仅当晚开放→少依赖在线生成）； ② 0 基础友好（纯静态网页 > 需要后端/算力）；③ 报告好写（每两周必有"能跑的新东西"可演示、可截图、可自证）； ④ 关于学校且能装二次元元素；⑤ 源码 zip ≤ 10MB（纯文本项目轻松满足）。

二、推荐课题构想：「SZTU 校园办事万事屋 · 二次元问答台」

2.1 一句话定位

把散落在学校官网、教务系统、宿管通知里的办事流程，整理成"提问 → 秒回答案"的网页问答台； 检索不到时再交给校内大模型兜底；全程由二次元看板娘"深小技"陪伴。

设计要点：离线优先——不依赖大模型也能用，规避"接口仅上课当晚开放"的硬约束； 数据与程序分离——同学/队友改 Markdown 就能加答案，不用碰代码。

2.3 二次元元素（对应课题要求）

  • 看板娘"深小技"：AI 生成的校园助手立绘（已生成 v1，位于 assets/mascot.png），常驻页面左上角；
  • 拟人化文案：空结果不冷冰冰，而是"深小技"道歉+引导换说法/提交新问题；
  • 表情气泡：命中多时开心、检索不到时沮丧颜文字（后期可用 CSS 切换立绘表情或加 Live2D 进阶）；
  • 加分想象：节日皮肤（开学季/考试周换装）、"深小技"语录随机彩蛋。

2.4 知识库数据规范（诚实工程，防"编造学校信息"翻车）

  • 每条 = 问题 + 分类 + 关键词 + 答案 + 来源；来源必须可指认（官网/通知/学生手册）；
  • 不确定的细节一律标 [待核实]，页面对应显示黄色角标——这本身就是一个可以写进报告的"数据质量机制"；
  • 数据收集方法：翻学校官网/迎新手册逐条整理，或用 WorkBuddy 联网检索后人工核对（AI 起草、人负责核实）。

3.4 GitHub 账号开通（唯一需要你亲手做的事，约 5 分钟）

  1. 打开 github.com → Sign up → 用你的常用邮箱注册（记牢用户名）；
  2. 把「用户名 + 注册邮箱」告诉我，我帮你改 Git 署名并建立远程关联；
