## 二、本周目标

1. 从 5 个候选题中确定选题，并给出可验证的验收标准；
2. 搭好 Git + GitHub 本地环境，让项目进入版本管理；

## 三、课题选择与收敛（为什么选它）

| 候选课题 | 难度 | 主要风险 | 结论 |
|---|---|---|---|
| **校园办事问答（含助手）** | 低 | 学校流程需逐条核实（已用 `[待核实]` 机制缓解） | **★ 选定** |
| 课程答疑知识库（含助手） | 中低 | 答案正确性难保证，需真实课程资料 | 备选（架构可复用） |
| AI 校园全能助手（AIGC） | 高 | "全能"范围失控，期末拿不出完整成果 | 不推荐 |
| 小说影视化流水线（AIGC） | 高 | 依赖生成算力，校内模型并发有限 | 不推荐 |
| AI 校园电台（AIGC） | 中 | 同上 + 音频资产管理繁琐 | 不建议 |

**决定性理由**：课程说明中"校内 AI 模型仅上课当天晚上开放、并发有限"是硬约束。
因此本项目采用**离线优先**架构——核心问答由"本地知识库 + 检索算法"完成，**完全不依赖大模型**；
校内模型只作为检索零命中时的兜底增强层。这样无论接口是否开放，程序都能演示、都能用。

**范围收敛**：放弃"全能助手"的发散设想，只做一件事——**办事流程问答**，
并限定在教务、宿舍、图书馆、校园卡、奖助、新生六大类。

### 4.2 可运行原型 v0.1.0
- **知识库**：`data/knowledge/*.md` 六类共 **31 条**问答，每条含
  `问题 / 分类 / 关键词 / 答案 / 来源`，不确定处统一标注 `[待核实]`；
- **数据流水线**：`scripts/build_index.py` 把 Markdown 解析成 `data/qa.json`，
  实现"数据与程序分离"——改答案不用碰代码；
- **前端**：`web/index.html` + `style.css` + `app.js`，原生实现搜索框、分类气泡、结果卡片；
- **二次元元素**：AI 生成看板娘「深小技」立绘（`assets/mascot.png`），
  页面左上角常驻，配拟人化文案（如检索无结果时"（；′д｀）ゞ 深小技没查到…"）。

### 4.3 关键修复 v0.1.1（本周最有价值的技术内容）
原型跑起来后发现**提问搜不到任何结果**，排查出两个真实缺陷：

1. **中文没有分词**：原逻辑把"图书馆几点开门"整体作为一个字符串去标题里 `includes`，
   标题里不可能有这串字 → 必然零命中。
   → 新增 `web/search-core.js`：中文按 2/3 字切片（n-gram）+ 剥离"怎么/如何/吗"等疑问词
   提取实词加权 + 同义词表（寝室→宿舍、一卡通→校园卡）+ 停用词过滤 + 相关度阈值，
   并按"标题 > 关键词 > 正文"三级权重打分。
2. **数据加载失败**：页面依赖 `fetch ../data/qa.json`，在双击打开/部分预览环境下路径与跨域被拦。
   → `build_index.py` 额外生成 `data/qa.js` 把数据内嵌；并新增 `scripts/build_standalone.py`
   产出单文件版 `dist/SZTU校园办事万事屋.html`（2.9MB，CSS/JS/数据/立绘全内嵌，断网可用）。
